# Single quality gate (`quality-gate`) — design

**Status: DRAFT, PENDING owner approval.** Branch `feat/quality-gate`, stacked on PR #79 (`feat/agent-platform`). Nothing here is approved, merged or deployed until N. G. Bonilla Vargas records it. Function 2 of `reports/Plan de agentes de vanguardia.md`.

Requirements: SRS Addendum C (REQ-FUNC-117, REQ-FUNC-118, REQ-SAFE-052, REQ-SAFE-053, REQ-SAFE-054). Hazard and controls: RMF Addendum C (HAZ-025; RC-122..RC-127). Traceability: Traceability Matrix, addendum "Single quality gate".

## 1. What it is

ONE deterministic function decides whether an AI step may run, and whether its output may be shown:

- when a study is opened for AI analysis (mode `single`: the in-browser FLAMeS segmentation), and
- when two visits are compared (mode `comparison`: `POST /segmentation/longitudinal/compare` and `/longitudinal/sel`).

It checks (a) that the image is a FLAIR, (b) the slice thickness of the acquisition, (c) in a comparison, whether the scanner (manufacturer, model, field strength) changed between the visits, (d) in a single study, that the image the AI reads has no skull. If a check fails, the step ABSTAINS and the physician reads why, in plain words, with what to do. It never continues silently.

It is a code-only agent: no language model, no tool, no network call. It is registered in the agent platform of PR #79 (`backend/app/agent_platform/agents.json`, id `quality-gate`) and so inherits the platform's identity, approval, kill switch (fail closed), trace and audit.

## 3. The decision rule (one rule, two implementations)

Input (normalised; both implementations take exactly this shape):

```
{ "mode": "single" | "comparison",
  "visits": [ { "sequence": "FLAIR"|"T1"|"T2"|"other"|"unknown"|"missing",
                "physician_confirmed_flair": bool,
                "thickness": { "state": "native"|"at_least"|"not_determinable", "effective_mm": number|null } | null,
                "scanner": { "manufacturer": str|null, "model": str|null, "field_strength_t": number|null } | null,
                "skull": "stripped"|"not_stripped"|"unknown"|"pending" } ],   // 1 visit (single) or 2 (tp1, tp2)
  "platform": { "allowed": bool, "code": str|null } }
```

Checks, in this order (a check that does not apply does not run and is not recorded):

| Check | Runs | pass | warn | pending | abstain |
|---|---|---|---|---|---|
| `platform` | always, first | the agent is approved and both switches read `on` | — | — | `gate_not_approved`, `gate_switched_off`, `gate_unavailable` (anything else, incl. unreachable). **Nothing else runs.** |
| `sequence` | per visit | `FLAIR` | `sequence_confirmed_by_physician` (unknown/missing + the physician's attestation, single study only) | — | `sequence_not_flair` (T1, T2, other — a confirmation never overrides a header that names another sequence), `sequence_unknown`, `sequence_missing` |
| `thickness` | per visit | `native` and ≤ 1.5 mm | `thickness_thick` (native > 1.5), `thickness_at_least` (lower bound only), `thickness_unknown` (not determinable, missing, invalid) | — | **none in this release** (REQ-SAFE-053): `thickness_out_of_range` only through the v3 evidence hook |
| `scanner` | comparison only, once | manufacturer, model and field strength recorded for both visits and equal (RC-062 tolerances) | `scanner_not_recorded` (nothing recorded in either visit: RC-062 then decides and abstains) | — | `scanner_changed` (fields named), `scanner_unknown` (one-sided or partial record) |
| `skull` | single study only (the comparison works on stored masks and normalises intensities inside the brain mask) | `stripped` | — | `skull_pending` (the image has not been read yet) | `skull_present`, `skull_unknown` |

Decision: any abstain → `abstain`; else any pending → `pending` (the AI may START, its output may not be shown); else any warn → `proceed_with_warnings`; else `proceed`. `ai_may_run` = decision ≠ abstain; `ai_output_allowed` = decision ∈ {proceed, proceed_with_warnings}.

### 3a. Sequence from the series description (first review of PR #81)

The description is split into tokens on every non-alphanumeric character, after splitting camelCase and reading `*` as `star` and `+C` as `postcontrast`. Any token of `other_words` (DWI, ADC, TRACE, STIR, DIR, PSIR, SWI, GRE, FFE, TOF, localizers, MPR/MIP/derived/subtraction, contrast, PD, …) or a T1 weighting together with a FLAIR name gives **other**, which always abstains whatever the physician confirms. A FLAIR, T2-FLAIR or dark-fluid name gives **FLAIR**. T1 / T2 weightings alone give T1 / T2; names such as SPACE, CUBE, VISTA, TIRM or IR alone give **unknown**, which only a physician's attestation can lift, in a single study. An inversion time below 1 400 ms gives other. Corpus: `frontend/src/config/qualityGate.sequences.v1.json` (G12, read by pytest and vitest).

Fifth review of PR #81 (D-QG-12, G19 extension), decided per word: the **weak** words `cal`, `loc`, `dir` and `mag` make an image *other* only when the description names no FLAIR, because each also has a harmless reading next to a FLAIR name — `cal` (calibrated, calvarium), `loc` (location), `dir` (the phase-encoding direction, `dir-AP` in BIDS-style names) and `mag` (every MR image is a magnitude image unless it is a phase map). Alone they still mean a calibration, a localizer, a double inversion recovery or a magnitude map, so `AX LOC` or `3D DIR SAG` stay *other*. Every other word of `other_words` keeps making the image *other* even with a FLAIR name, each with a reason: `pha` (a phase map is not an intensity image), `pc` (phase contrast or post-contrast — neither a plain FLAIR), `epi`/`ep2d` (echo-planar FLAIR: distortion and a noise texture the model was not validated on), `trace`/`dwi`/`adc` (diffusion), `gre`/`swi`/`star` and the gradient-echo SequenceName codes (susceptibility or gradient echo), `stir`/`psir` (other inversion recovery), the contrast and reformat words (D-QG-7). The generated corpus of the flags-off snapshot loses no base FLAIR acceptance outside these documented decisions (`test_rc122_flags_off_identity.py`, `headerEvidence.flagsOff.test.ts`).

Seventh review of PR #81 (S1; D-QG-7, D-QG-11, D-QG-14): a DICOM ImageType value that says the image is not an original acquisition makes it *other*, each for its reason — DERIVED (value 1: computed from other images), SECONDARY (value 2: made after the examination, a secondary capture), MPR / REFORMATTED / RESAMPLED (re-sliced: the voxels are interpolated, so lesion edges and volumes change), MIP / MINIP / PROJECTION IMAGE (projections, not slices), SUBTRACTION (a difference image), LOCALIZER (a planning image), SCREEN SAVE (a picture of a screen), and the parametric maps ADC / TRACEW / FA / perfusion / EXP (not a FLAIR contrast). ORIGINAL, PRIMARY and the vendor flags of an original acquisition (M, ND, NORM, DIS2D, OTHER, M_SE) say nothing. Corpus: 15 ImageType entries. **Changed by the ninth review (G33):** DERIVED alone no longer makes an image 'other' — a scanner writes DERIVED\PRIMARY for an acquisition it corrected on the console (NORM, DIS2D, DIS3D, FILTERED, MFSPLIT), and those images are the FLAIR the physician reads; they now say nothing and give no warning. DERIVED\SECONDARY stays 'other' (through SECONDARY), as do all the other markers above.

The physician's attestation is a separate control in the card, offered only when the sequence is unknown or missing, unticked, reset per file, sent only on Run and before the result, a strict boolean on the route, recorded in the audit code with the clinician. In a comparison it is offered per visit (F1, third review); it is kept for the pair it was given for — a refresh after a radiologist decision, the Compare button and the SEL search send it again — and dropped when the pair or a file changes (fifth review, F1/F2). It is read by the longitudinal routes only while `QUALITY_GATE_ENFORCED` is on; with the gate off it is ignored, as on the base branch (G26).

The rule and its parameters live in ONE policy file, read only by the server: `backend/app/services/quality_gate_policy.json` (sixth review of PR #81, G27: the browser holds no copy; the registry entry records its SHA-256). The server reads everything the browser's RC-049 used to read — DICOM SeriesDescription, ProtocolName, SequenceName, ImageType and InversionTime; the NIfTI descrip, aux_file, intent_name and db_name, the printable text of NIfTI extensions and the DICOM attributes of a DICOM extension — together with the series description stored for the file (D-QG-13).

## 4. Where it is consulted

- **Backend** `app/services/quality_gate.py`: `evaluate()` (pure), `run_quality_gate()` (platform check, one trace with one child span per check that ran, one audit record — `agent.run` (CLINICAL_AI_RUN) only when the decision releases an AI output, `agent.consultation` (QUALITY_GATE_CONSULTATION) otherwise; fifth review, F4), input derivation from stored metadata, and `apply_to_comparison()` (withholds the same fields as RC-062).
- **Backend route** `POST /api/v1/clinical/quality-gate` (in `clinical_tools.py`, CAPA-009 `_authorized_inputs`): the single-study gate before the AI, inputs derived on the server from the stored file; audited by the middleware as a consultation (F4). Fifth review, F3: the answers to pre-run consultations are cached per (file, version, attestation, skull, policy version) and a repeated consultation is served from the cache without counting; only real evaluations (refusals included) count against the per-user limit (30 per minute); a consultation that would release an output (skull reported) is never served from the cache. Over the limit: HTTP 429 with the seconds to wait; the panel says "too many checks, wait N s" (`gate_rate_limited`), never "unavailable". **Known limitation:** the limiter and the cache live in each server instance's memory, so with N instances a user can make up to N × 30 real evaluations per minute, and a cached answer is reused only on the instance that made it.
- **Longitudinal routes**: when `QUALITY_GATE_ENFORCED` is true, the gate decides BEFORE any mask, image, registration or atlas is loaded, and an abstention returns at once with every quantity withheld; each visit is derived exactly as a single study (sixth review, A1: its stored image header, its stored series description, its acquisition record — read once and reused by RC-062); the gate's plain reasons are appended to RC-062's caveat. The physician's attestation is read only while the gate is enforced (G26).
- **Frontend** `src/services/qualityGate/gate.ts`: DISPLAY AND REQUEST ONLY (sixth review, G27). The card sends the file, the attestation (on Run) and the worker's skull outcome (final consultation) and shows the server's answer as it is; the answer names the attestable visits and the action of each code; RC-049 in the worker takes the server's class. A rate-limited or unavailable answer is asked again by itself after the server's wait, with a countdown (U2); the final decision belongs to the run (U3); a comparison's attestations for a pair add up (U1). `QualityGatePanel` shows the result; all text comes from the i18n files (en/es/de), keyed by code. Behind `VITE_ENABLE_QUALITY_GATE` (OFF).

## 5. Invariants (closed by the combinatorial matrix, `backend/tests/unit/test_quality_gate_matrix.py`)

Matrix: sequence {FLAIR, T1, T2, unknown, missing} × physician confirmation {no, yes} × thickness {≤ 1.5, (1.5, 4.5], (4.5, 6.5], > 6.5 mm, unreadable} × scanner {same, other manufacturer, other field strength, unknown} × skull {stripped, not stripped, unknown, pending} × mode {single, comparison with tp1 affected, tp2 affected, both} = **3 200 cases**, plus the platform states {on, switched off, not approved, unavailable, unknown} over the whole matrix.

- **G1** The AI never runs on a non-FLAIR or unknown sequence (a physician confirmation lifts `unknown`/`missing` only, never a header that names another sequence, and always leaves a warning).
- **G2** Every abstention, warning and pending state carries a machine-readable code; every code has a plain message and an action in en, es and de in the i18n files.
- **G3** No `pass` from an unknown, unreadable, missing or pending value; `proceed` only when every input is known and good.
- **G4** *(replaced by G27, sixth review of PR #81: there is one implementation, so there is nothing to keep in step)*
- **G5** The trace records exactly the checks that ran, with their status and code (one child span each), and one audit record per consultation.
- **G6** Kill switch off, agent not approved, registry or switch unreadable, backend unreachable → no AI step proceeds, and the reason is shown.
- **G7** (data rule) The thickness check never abstains while no evidence asset with a commercial licence (CC0-1.0, CC-BY-4.0) is set; the shipped policy has none and names no non-commercial dataset.
- **G8** *(replaced by G24, fourth review of PR #81.)*
- **G9** Deterministic, and independent of what does not apply (a single study ignores the scanner; a comparison ignores the skull).
- **G10** Monotone: making one input worse never turns an abstention into a run.
- **G11** No output while a check is pending.
- **G12** Shared corpus of series descriptions: each gets its class in backend and browser; a non-FLAIR name always abstains.
- **G13** The attestation lifts only unknown/missing, only in a single study, and is never sent implicitly.
- **G14** Every suggested action is possible in its mode.
- **G15** *(restated in the fifth review, made structural in the sixth by G27)* One sequence classifier, the server's; with the gate ON the RC-049 header evidence takes the class the server returns; with it off RC-049 keeps its base rules (G26); the research inventory always keeps its base heuristic.
- **G16** When the gate stops a comparison, only its reason is shown.
- **G17** The decision that releases or withholds the output is decided and audited by the server, with the deciding code.
- **G18** No stale answer acts: every consultation and run names its file and version; one request at a time.
- **G19** Field-aware classification; nothing accepted as FLAIR before PR #81 is lost except documented decisions (pre-PR snapshot, `scripts/safety/quality_gate_pre_pr_snapshot.py`).
- **G20** Only descriptive fields are classified; identifiers never change the class.
- **G21** One coherent verdict per gate decision × RC-062 status.

- **G23** The card always reaches a decided state for the selected file.

## 6. Data rule and the v3 hook (REQ-SAFE-053)

Thresholds or figures that ship may come only from commercially usable data (DLBS, CC0; MSLesSeg, CC BY), never from SibBMS or WMH 2017 (non-commercial). The controlled-thickness experiment of paper 1 (commercial data only) is still running. Until it lands:

- the thickness check WARNS and explains (band named, "small lesions may be missed; a 3D FLAIR ≤ 1.5 mm is recommended"); it does NOT abstain;
- the band limits are the pre-registered protocol limits, used only to name the band;
- **hook** — `policy.thickness.evidence_asset` (`null` today). When the v3 asset lands, it is set to `{ "asset_id", "version", "sha256", "licence", "abstain_band_ids" }`. Both implementations abstain on a band only when the licence is in `commercial_licence_allowlist`; any other licence keeps the warning. Setting it is an owner decision (D-QG-4) and a new review of this document.
