# Viewer v3 — parity evidence: in-browser 2D rendering vs the server PNG path

Status: **parity demonstrated on code and data; server PNG path kept as fallback**
until the owner signs off a clinical visual check on real studies (see "Retiring the
fallback"). Branch `feat/viewer-v3`.

## What is compared

| | Server path (legacy, still available) | Browser path (v3 default) |
|---|---|---|
| Source | `ImagingService.load_nifti` → `normalize_to_uint8` (global min–max, truncation) → `pixel_array[:, :, k]` → 8-bit PNG per slice | `/imaging/nifti` bytes parsed in the browser (`frontend/src/volume/nifti.ts`) |
| Bit depth | 8 bit, windowed once on the server | stored values after header scaling (float64 math) |
| Window/level | server round-trip (matplotlib) or CSS filter | local repaint, real units |
| Planes | k only, array order (rotated 90° for RAS/LAS data) | axial / coronal / sagittal from the affine, or array order |

## 1. Pixel parity against the REAL server code (committed, runs in CI)

`frontend/src/volume/parity.test.ts` + fixture `frontend/src/volume/__fixtures__/parity-cases.json`
generated by `scripts/viewer/build_parity_fixture.py`, which runs each NIfTI through
the backend's own `ImagingService.load_nifti` and `process_image` and stores the
decoded PNG pixels, the metadata, and nibabel's affine / axis codes / scaled values.

10 asymmetric volumes (n0 ≠ n1 ≠ n2, voxel value encodes (i, j, k)):
int16 LAS with `scl_slope=2.5, scl_inter=-10`; float32 RAS gzipped; uint8 permuted
axes with qform only (PSL); float64 oblique 30°; big-endian int16 (LPS); singular
affine (orientation UNKNOWN); uint16; int8 oblique 50° (ALS); float32 sheared; a 3-D
oblique where a naive per-column argmax would name the same world axis twice.

Asserted for every case (55 tests): grid, zooms, scaled probe voxels, global min/max,
affine (sform > qform > base precedence), axis codes equal nibabel and the server's
`anatomical_orientation`, **every server PNG slice reproduced pixel-for-pixel**, and the
fail-closed agreement check passes (and refuses on a grid / spacing mismatch; drops
anatomical views on an orientation disagreement or a missing server orientation).

## 2. Pixel parity on a real public MS study (local, gitignored data)

`frontend/src/volume/parity.realcase.test.ts` (skipped automatically when the data is
absent, e.g. in CI). Data: open_ms_data `cross_sectional/MNI/patient01` (CC-BY,
Lesjak et al. 2017), fixtures by `scripts/viewer/build_demo_fixtures.py` using the
backend's own code.

Result on 2026-10-17: FLAIR and T1, 182 slices each, 182 × 218 px —
**0 differing pixels out of 14 442 064** compared; metadata agreement check passes
(grid, spacing, orientation LAS); the expert lesion mask, read through the three
anatomical views, equals the expert NIfTI at the displayed voxel for > 10 000 sampled
pixels per run.

## 3. Overlay alignment, painting and undo in all three planes

- `frontend/src/volume/maskPlane.test.ts` — asymmetric 6 × 9 × 4 image and mask whose
  values both encode the voxel: for every view (array order + anatomical for LAS / PSL
  / ALS, both conventions), every slice and every pixel, the mask pixel drawn equals the
  image grey drawn. Painting a 1-voxel dab sets exactly `voxelOf(view, slice, r, c)`
  and is drawn back at (r, c); brushes never leak into another slice; draw-over
  protection holds; undo snapshot/restore is lossless; the legacy swapped-axes mask
  layout is supported by the same rule as before; on the legacy view the new code is
  bit-identical to the legacy canvas (subarray / transposeSlice / circular brush).
- `frontend/src/hooks/useSegmentationMask.planes.test.ts` — the real hook: plane
  painting, undo/redo across planes in LIFO order interleaved with the legacy k-slice
  path, draw-over, fail-closed stale grid.
- `frontend/src/volume/sliceGeometry.test.ts` — screen↔voxel bijection on an
  asymmetric grid; a laterality phantom (markers placed by WORLD direction through the
  affine, 6 affines incl. permuted and oblique) lands where the display convention
  says; radiological only mirrors left/right of axial and coronal.
- Visual: `screenshots/after-14 … after-16` — a stroke painted in the sagittal plane
  appears in the axial plane as a line at exactly the sagittal position, and Ctrl+Z
  removes it.

## 4. Measurements

`frontend/src/volume/viewportTransform.test.ts`: the client transform keeps the
physical aspect of anisotropic reformats and round-trips screen↔image at any zoom/pan;
measurements use `[rowSpacing, colSpacing]` of the displayed axes. The same file pins

## Fail-closed behaviour kept in production code

- Browser reading disagrees with `/imaging/metadata` on grid or voxel spacing, the file
  is DICOM, or the NIfTI encoding is unsupported (RGB, complex, 64-bit ints, `ni1`
  pairs) → automatic switch to the server PNG path with a visible notice.
- Orientation indeterminate, no sform/qform (Analyze default), or browser and server
  codes disagree / server code missing → images shown in voxel order, planes named k / j
  / i, explicit "orientation not established" notice. Never a guessed anatomical name.
- A mask, zone map, conformal map or longitudinal map on another grid → not drawn,
  notice shown (never stretched).

## Retiring the fallback (not done — needs the owner)

1. One visual check by a clinician on 3–5 real studies (axial / coronal / sagittal,
   overlay, a painted correction saved and reloaded).
2. Decide the display convention for 2D *and* 3D (`DISPLAY_CONVENTION` in
   `frontend/src/volume/sliceGeometry.ts`; neurological today = what the 3D view always
   showed; radiological is the PACS norm).
3. Then remove `standard` / `matplotlib` from the menu and the
   `/imaging/process` PNG payload from the default load (already not requested on the
   browser path).
